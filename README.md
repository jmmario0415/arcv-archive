# Arc-V 대회 기록

공개 사이트: https://jmmario0415.github.io/arcv-archive/
저장소: https://github.com/jmmario0415/arcv-archive

## 기능

- 제공받은 1~4회 기록, 플랫폼 필터, 우승자/덱/회차 검색
- 새 대회 기록 등록, 기존 대회의 썸네일 및 덱리 등록
- 사진 파일 선택, 미리보기, Supabase Storage 업로드
- JPG, PNG, WebP, GIF: 한 장당 5MB 이하
- 덱리 텍스트와 외부 영상/덱리 링크
- 로그인이나 운영자 승인 없이 등록 후 즉시 공개

이미지를 선택하지 않으면 해당 대회에 저장된 이미지가 유지됩니다.
새 이미지 등록은 기존 사진을 덮어쓰지 않고 새 URL을 생성합니다.
공개 버킷이므로 업로드된 사진은 주소를 아는 누구나 볼 수 있습니다.
방문자에게 기존 파일의 덮어쓰기/삭제 권한은 부여하지 않습니다.
공개 가능한 닉네임과 이미지만 등록해주세요.

## 구성

- index.html, style.css, theme.css: 화면
- app.js: 대회 기록 조회/등록
- uploads.js: 파일 검증, 미리보기, 바이너리 업로드
- config.js: Supabase 프로젝트 URL과 브라우저용 publishable key (비밀 키 사용 금지)
- data.js: DB 조회 실패 시 제공받은 기본 4개 기록
- supabase.sql: 대회/덱리 테이블, 권한, 초기 기록 및 즉시 공개 정책
- storage-uploads.sql: duel-images 공개 버킷과 새 파일 업로드 정책

## 운영

DB는 Supabase tournaments와 tournament_media 테이블을 사용합니다.
각 대회의 가장 최근 공개 tournament_media 등록 내용이 표시됩니다.
approved 필드는 호환성 때문에 유지하되 새 등록의 기본값은 true입니다.
기존에 승인 대기 상태로 제출된 내용은 자동 공개하지 않습니다.
기존 기록 정정이나 삭제는 운영자가 Supabase 대시보드에서 수행합니다.

파일 업로드 후 기록 저장에 실패하면 입력과 파일 선택을 유지합니다.
같은 창에서 재시도하면 업로드가 끝난 파일을 재사용합니다.
창을 닫거나 새로고침하면 업로드 캐시는 사라집니다.
기록에 연결되지 않은 파일은 운영자가 Storage에서 확인해 정리할 수 있습니다.

## 실행 및 배포

로컬 실행: python -m http.server 4173 --bind 127.0.0.1
검사: node verify.cjs
별도 빌드 없이 GitHub Pages의 main / (root)에서 자동 배포합니다.
배포할 때 uploads.js를 포함한 모든 런타임 파일을 함께 올립니다.

## 기본 정보 수정
각 대회의 기본 정보 수정에서 회차·날짜·플랫폼·인원·방식·우승자·덱 이름·메모를 수정합니다. basic-edit.sql의 RPC는 로그인 없이 사용할 수 있습니다. 직접 UPDATE/DELETE 권한을 부여하지 않고 지정한 기본 정보만 수정합니다. 중복 회차와 동시에 변경된 기록은 거절됩니다. 회차를 바꾸면 사진과 덱리의 연결도 같은 트랜잭션에서 이동합니다.

## 대진표와 기록실 통합

같은 GitHub Pages 사이트의 루트는 기록실, duel/은 대진표 메이커입니다. 두 화면의 메뉴로 이동합니다.
제공받은 ZIP의 리그/토너먼트 계산, 승패 기록, 순위표, 결과 매트릭스, MQTT 토픽 및 저장 방식, 삭제 기능, 이미지와 avatars.js는 유지했습니다.
우승 확정 후 대회 화면의 ‘기록실에 등록’을 누르면 기존 기록실 등록 폼에 우승자, 참가 인원, 생성일 기준 날짜, 진행 방식을 가져옵니다. 플랫폼과 매치 여부는 대회 이름에서 추정하므로 저장 전에 확인합니다. 직접 입력 대진은 리그로 가져오며 메모에 표시합니다.
회차는 다음 회차를 제안합니다. 사용 덱과 사진/덱리를 보완하고 등록하면 Supabase에 즉시 저장됩니다. 원본 대회 ID의 중복 등록은 DB에서 차단합니다.
공동 우승은 이름을 ‘ · ’로 연결합니다. 50자를 넘으면 메모에 남기고 우승자 필드를 직접 입력하게 합니다.
등록 시 원본 대진표 링크, 참가자, 승패 결과와 당시 최종 순위를 source_snapshot으로 함께 보관합니다. 원본 대진표는 이후에도 실시간으로 바뀔 수 있지만 저장 시점의 스냅샷은 별도입니다.
이미 수동으로 입력한 과거 기록에는 원본 대회 ID가 없으므로 해당 기록과의 자동 중복 판별은 하지 않습니다.
동일 출처 내의 sessionStorage로 입력 정보를 옮기므로 저장 공간 차단 시 안내합니다. 이동만으로 저장되지 않고 기록실 폼에서 최종 등록합니다.
integration.sql을 기존 DB에 추가 실행합니다. 메이커의 원래 외부 사이트는 수정하지 않으며 통합 사이트에서도 같은 공개 MQTT 저장소를 공유합니다.
검사: node verify.cjs 및 node verify-merge.cjs

## 멤버 등록과 참가자 자동완성

상단 ‘멤버’ 메뉴에서 닉네임(1~12자)과 사진을 등록합니다. 기존 8명은 원래 이미지를 유지한 채 club_members 테이블에 초기 등록합니다. 띄어쓰기와 대소문자를 무시한 이름 중복은 DB에서 차단합니다. 같은 멤버의 사진을 바꾸려면 목록의 ‘사진 수정’을 이용합니다. 이름 변경/멤버 삭제 기능은 포함하지 않습니다.
대진표의 참가자 입력란은 등록된 멤버를 자동완성으로 제시하고 일치한 이름에 사진을 표시합니다. 직접 입력 대진에서는 ‘등록 멤버 검색 → 이름 넣기’로 편집 중인 위치에 이름을 넣을 수 있습니다. 등록되지 않은 이름도 기존처럼 직접 입력할 수 있습니다.
기존 순위, 대진, 실시간 승패 저장과 대회별 덱 썸네일은 변경하지 않습니다. 멤버 저장소 연결 실패 시 기존 8명의 사진을 사용하며 대진표 기능은 유지됩니다. 저장소가 연결되지 않은 멤버 관리 화면에서는 신규 저장을 비활성화합니다.
DB 설정: members.sql. 초기 설정 후 정책을 재생성할 때는 동일 이름의 정책 중복에 주의합니다. 공개 읽기/추가 및 지정된 멤버 사진 수정 RPC만 허용하며 멤버 사진 열만 UPDATE를 허용하며 이름 변경이나 DELETE 권한은 부여하지 않습니다.

## 경기별 단판/매치 스코어

새 대회에서 경기 단위를 단판(1선승) 또는 매치(2선승, 최대 3판)로 선택합니다. 단판은 기존처럼 승자를 눌러 기록할 수 있습니다. 매치는 참가자나 스코어 버튼을 눌러 2:0, 2:1 등을 기록합니다. 진행 중 스코어(1:0, 1:1 등)도 저장할 수 있으며, 확정 전에는 승리로 집계하지 않습니다. 기존 대회도 스코어 버튼에서 경기별 매치 기록을 입력할 수 있습니다.
결과는 기존 MQTT 경기 결과 키에 {a,b,sa,sb,format} 형태로 저장합니다. 기존 정수형 승자 기록도 계속 읽습니다. 순위표는 경기/매치 승패를 기준으로 유지하고 매치는 세트 승패도 함께 표시합니다. 토너먼트 앞 경기의 승자가 바뀌거나 기록이 취소되면 연결된 상위 라운드 기록만 초기화하며, 같은 승자의 세트 스코어 수정은 다음 라운드를 유지합니다.
기록실로 등록할 때 경기 단위, 스코어와 세트 승패를 함께 스냅샷으로 남깁니다. 이미 저장된 과거 기록은 자동 변경하지 않습니다.
상단 로고는 전체 페이지의 Arc-V 텍스트로 통일했고, 기록실/멤버 하단 푸터를 제거했습니다. 대진표 히어로 이미지는 페이지를 새로 열 때 멤버 썸네일 중 하나를 무작위로 선택합니다.
검사: node verify-scoring.cjs
